# A14 장바구니 · 결제 · 주문 내역

작업 브랜치는 `feature/cart-checkout`이다. 화면 테스트는 실제 라우터와 인증·장바구니 Provider에 메모리 API를 연결해 실행했다.

| 요구사항 | 구현 및 검증 |
|---|---|
| SH-01 | 메뉴소개에서 대표 카드와 일반 카드의 본문 안에 담기 버튼을 배치했다. 온도가 두 가지인 메뉴는 HOT/ICE를 선택할 수 있다. 테스트에서 두 카드의 담기 결과, 디저트의 온도 값, 메뉴명을 읽는 상태 메시지와 홈 대표 카드의 기존 구성을 확인했다. |
| SH-02 | 헤더는 전체 수량을 읽고 장바구니는 온도별 수량·금액과 합계를 표시한다. 테스트에서 1개와 20개의 경계, 변경 후 합계, 삭제 취소와 확정 시 포커스, 마지막 항목 삭제 후 메뉴 링크를 확인했다. 변경이 실패해도 기존 항목을 표시하며 다시 불러온 뒤 결제할 수 있다. |
| SH-03 | 게스트가 담은 메뉴를 화면을 다시 연 뒤에도 표시한다. 결제 링크의 로그인 복귀 경로는 `/checkout`이다. 비회원의 직접 접속, 로그인 후 동일 메뉴·온도의 수량 병합, 처리 중인 담기가 끝난 뒤 결제 합계를 표시하는 경우를 검증했다. |
| SH-04 | 받는 방법과 결제 방법은 각각 필수 라디오 그룹이다. 빈 양식을 제출하면 설명이 연결된 첫 오류 항목으로 포커스가 간다. |
| SH-05 | 테이크아웃·매장에서 각각 현장 결제·온라인 결제를 선택해 총 네 조합으로 주문을 저장했다. 완료 화면의 수령·결제 방법과 금액까지 검사했다. |
| SH-06 | 주문 전에 모의 주문임을 알린다. 온라인 결제 창에는 금액, 승인, 취소가 있다. 네 조합 모두 메모리 백엔드의 화면 테스트에서 fetch 호출이 0건이었고 결제 정보 입력란도 없었다. |
| SH-07 | 주문 저장과 장바구니 비우기는 기존 주문 API에 맡겼다. 지연된 응답에 더블 클릭해도 호출은 한 번이었다. 결제 취소, 저장 실패 후 재시도, 저장 성공 후 장바구니 조회 실패를 각각 검사했다. 성공 시 주문 상세가 결제 경로를 대체하여 뒤로 가면 장바구니로 돌아간다. |
| SH-08 | 내역은 최신순이며 상세는 저장된 주문번호, 메뉴·온도·수량·금액, 결제 상태를 표시한다. 계정을 바꾸면 이전 주문은 찾을 수 없다는 안내가 나온다. 내 리뷰를 조회해 같은 주문·메뉴에만 수정 링크를 제공하고 두 온도로 산 메뉴에는 리뷰 링크를 한 개만 표시한다. |
