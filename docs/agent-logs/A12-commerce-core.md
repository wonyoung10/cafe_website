# A12 회원·구매·리뷰 프런트엔드 기반

작업 브랜치는 `feature/commerce-core`다. 화면 담당자는 `@/contexts`에서 `useCommerce`, `useAuth`, `useCart`를 가져올 수 있다. 테스트에서 `renderApp(path, { api })`로 같은 계약을 구현한 API를 주입할 수 있다.

## 구현 범위

| 요구사항 | 구현 및 확인 |
|---|---|
| AU-01~07 | 세션 조회·구독·가입·로그아웃, 대소문자를 구분하지 않는 로그인, 입력 규칙과 공통 오류를 제공한다. Supabase 이메일 확인이 켜져 있으면 설정 안내를 반환한다. 메모리 모드는 계정별 난수 salt와 Web Crypto SHA-256 해시를 저장한다. 가입·로그인 폼과 비밀번호 확인 입력은 A13 범위다. |
| SH-01~03 | 메뉴와 온도 조합, 수량 1~20을 검증한다. 게스트 저장소를 읽을 때 손상된 행을 걸러낸다. 병합에 성공한 뒤 게스트 항목을 지우며 이후 목록 조회 실패 시 재병합하지 않는다. 계정 전환 뒤 늦게 끝난 읽기와 StrictMode에서의 중복 병합을 테스트했다. |
| SH-04~08 | 두 받기 방식과 두 결제 방식, 메뉴 가격 스냅샷, 빈 카트 거절, 개인별 주문 내역·상세를 구현했다. 메모리 계약 테스트에서 동시 주문 두 건 중 한 건만 성공한다. Supabase는 주문 전용 RPC를 호출한다. 결제 화면과 모의 결제 확인은 A14 범위다. |
| RV-01~06, RV-08~09 | 구매 여부·중복·소유권 검사, 마스킹된 공개 목록, 내 리뷰·메뉴 필터·정렬, 수정·삭제를 제공한다. 남의 주문 번호와 회원 식별자는 공개 목록에 포함되지 않는다. 별점 평균 표시와 삭제 확인은 A15 범위다. |
| RV-07 | 1~5 정수 별점과 양끝 공백을 제거한 1~500자 글을 검사한다. 저장용 사진은 JPEG·PNG·WebP, 최대 2 MiB다. 메모리는 data URL을 저장한다. Supabase는 추가·교체 실패 시 새 파일을 회수하고 이전 파일은 행 변경 성공 뒤 정리한다. 10 MB 원본 입력과 1200 px 리사이즈는 A15 범위다. |
| §3~4 공통 | 타입 계약, 오류 코드, SDK 지연 로드, 환경 변수 예시, 안전한 복귀 경로, 보호 경로와 로딩·오류·준비 안내를 추가했다. 새 경로 9개에 지연 로딩 페이지 8개를 연결했다. 리뷰 작성·수정은 같은 페이지를 쓴다. 헤더에 네 번째 메뉴인 리뷰와 장바구니·계정 진입점을 배치했다. |

`useCart().status`는 `loading`, `ready`, `error`다. `reload()`는 실패한 병합과 목록 읽기를 다시 시도한다. 게스트 저장소 접근은 Web Locks를 지원하는 브라우저에서 탭 간 직렬화한다. Web Locks가 없으면 현재 탭의 작업을 순서대로 처리한다.

Chromium 실행 시 샌드박스가 macOS Mach 포트 등록을 거부해 헤더의 실제 브라우저 렌더링과 스크린샷은 확인하지 못했다. 실제 Supabase 프로젝트의 Auth·PostgREST·Storage 연동은 확인하지 않았다. 이 브랜치에서 검증한 대상은 메모리 구현과 모의 Supabase 클라이언트다.
