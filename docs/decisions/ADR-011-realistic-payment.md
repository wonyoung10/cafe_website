# ADR-011 실제 결제처럼 진행되는 모의 결제

- 날짜: 2026-11-25
- 상태: 채택 (2026-11-25 사용자 승인으로 main 병합). ADR-008의 '승인/취소만 있는 모의 결제 창'을 대체하고 나머지는 유지한다.

## 배경
사용자가 "결제 모의를 실제 결제 하는 것처럼" 만들어 달라고 했다. 사이트는 공개 배포되어 있어 카드 정보 입력란을 두면 방문자가 실제 정보를 넣을 수 있다.

## 검토
| 항목 | 고른 것 | 고르지 않은 것과 이유 |
|---|---|---|
| 결제 정보 | 준비된 가상 카드·간편결제 선택, 앱 인증 흉내 | 카드번호·비밀번호 입력: 실제 정보가 들어올 수 있다 |
| 이름·모양 | 지어낸 이름과 이 사이트의 색·모서리 | 실제 카드사·간편결제 이름·로고: 사칭이 된다 |
| 승인 번호 | 주문 id에서 계산 | DB 열 추가: 운영 DB 변경과 배포 순서 조율이 필요하다 |
| 결제수단 기록 | 결제한 브라우저에만 | DB 저장: 위와 같음. 필요해지면 `orders`에 열을 더하고 `place_order`를 바꾸며, 적용 전 사용자 확인을 받는다 |
| 응답을 잃은 결제 | 주문 목록으로 결과 확인 | 바로 실패 처리: 이미 만들어진 주문을 다시 결제하라고 안내하게 된다 |

## 결정
결제창을 확인 → 앱 인증 → 승인 처리 → 완료·실패 단계로 나누고 `place_order`는 그대로 쓴다. 한도 초과 같은 거절은 브라우저에서 만든 연출이며 DB에 남지 않는다. 모의 결제 안내는 결제 화면, 결제창 위쪽, 영수증에 항상 보인다.

## 결과
- DB 변경이 없어 화면만 배포하면 된다. 이전 주문의 영수증에도 승인 번호가 나온다.
- 다른 기기나 저장소를 지운 브라우저에서는 영수증의 결제수단이 '온라인 결제'로만 보인다.
- 한도·인증은 브라우저 안에서만 검사하므로 API를 직접 부르면 건너뛸 수 있다. 실제 돈이 오가지 않아 수용한다.
- 승인 번호와 영수증은 모의 값이며 결제 증빙이 아니다.
