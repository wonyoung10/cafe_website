형식: **상태 / 맥락 / 결정 / 결과(트레이드오프)**. 새 결정은 `ADR-NNN-<slug>.md`가 아닌 이 파일에 이어서 기록한다(과제 규모상 단일 파일로 관리).

## ADR-001 React + Vite + TypeScript (Next.js 미사용)
- **상태**: 확정 (2026-11-16)
- **맥락**: 과제 요구사항이 React + Vite + TS를 필수로 지정, Next.js 사용 금지. 서버 기능 불필요.
- **결정**: Vite SPA, TS `strict`.
- **결과**: 정적 호스팅 가능. SEO는 정적 메타 태그 수준으로 제한(과제 범위상 수용).

## ADR-002 React Router DOM 선언형 `BrowserRouter`
- **상태**: 확정
- **맥락**: v7은 데이터 라우터(`createBrowserRouter`)와 선언형(`BrowserRouter`) 모두 지원. 과제가 `BrowserRouter`·`Routes`·`Route`·`NavLink` 학습을 명시. 로더/액션 불필요.
- **결정**: `<BrowserRouter>` + `<Routes>` 선언형. 스크롤 복원은 커스텀 `ScrollToTop`(데이터 라우터 전용 `ScrollRestoration` 대신).
- **결과**: 테스트에서 `MemoryRouter`로 손쉽게 대체 가능. 뒤로가기 시 이전 스크롤 위치 복원은 하지 않음(최상단 이동) — 소개 사이트 특성상 수용.

## ADR-003 절차적(Procedural) 3D 모델링
- **상태**: 확정
- **맥락**: 실제 도면·3D 모델 없음, 외부 GLB는 용량·라이선스 부담. 학습 목표상 Three.js 지오메트리·재질·조명 직접 다루기가 유리.
- **결정**: 모든 가구·공간을 R3F 기본 지오메트리와 캔버스 절차적 텍스처로 구성. HDR 환경맵 미사용.
- **결과**: 로딩이 빠르고 오프라인 동작. 사실감은 사진 수준이 아닌 '스타일라이즈드 미니어처' 톤.

## ADR-004 브랜드 정보 단일 소스
- **상태**: 확정
- **맥락**: 브랜드명 '하루의 잎'은 임시.
- **결정**: 이름·카피·철학은 `src/data/brand.ts`, 로고는 `BrandLogo` 컴포넌트, 메타 태그는 빌드 시 `index.html`의 `%BRAND_NAME%` 대신 단순 문자열(변경 지점 README에 명시).
- **결과**: 이름 확정 시 `brand.ts` + `index.html` title 두 곳만 수정.

## ADR-005 지도: OpenStreetMap 임베드 + 네이버/카카오 링크
- **상태**: 확정
- **맥락**: 네이버/카카오 지도 JS SDK는 API 키·도메인 등록 필요 → 과제 환경에서 재현성 낮음.
- **결정**: 지도 표시는 키가 필요 없는 OSM `export/embed.html` iframe. 길찾기는 네이버지도·카카오맵 웹 URL 링크. 좌표는 공개 지오코딩으로 주소 확인 후 적용, 확인 결과를 `src/data/cafe.ts` 주석에 기록.
- **결과**: 키 없이 동작. 지도 스타일은 OSM 기본.

## ADR-006 Tailwind CSS v4 `@theme` 토큰
- **상태**: 확정
- **결정**: `tailwind.config.js` 없이 CSS-first 설정(`@tailwindcss/vite`), 토큰을 CSS 변수로 노출해 3D 씬(`tokens.ts`)과 값을 맞춤.

## ADR-007 Codex 에이전트는 커밋하지 않음
- **상태**: 확정
- **맥락**: Codex `workspace-write` 샌드박스는 worktree 밖(`.git/worktrees/*`) 쓰기를 막을 수 있음. 또한 병합 전 리뷰 게이트 필요.
- **결정**: Codex는 파일만 수정, 총괄(A01)이 리뷰 후 커밋(본문에 에이전트·모델 기록).
- **결과**: 모든 커밋이 리뷰를 거침. 에이전트별 커밋 이력은 커밋 본문 `Agent:` 줄로 추적.

## ADR-008 의존성 사전 설치
- **상태**: 확정
- **맥락**: Codex 샌드박스는 네트워크 차단.
- **결정**: 기반 단계에서 필요한 모든 패키지를 설치·잠금. 에이전트는 새 패키지 추가 불가.

## ADR-009 '하루의 빛' 시간대 조명
- **상태**: 확정 (2026-11-16)
- **맥락**: 디자인 다듬기 이후 시그니처 요소(홈 `WeekBranch`)가 홈에만 있어 3D 매장 페이지와 브랜드 메시지('하루')의 연결이 약했다.
- **결정**: 3D 매장에 아침·오후·저녁 조명 프리셋과 전환 UI를 둔다. 기본값은 방문 시각. 새 광원을 추가하지 않고 기존 햇빛·반구광·펜던트의 값만 보간한다. 프리셋은 three.js와 분리된 순수 데이터로 두어 단위 테스트한다.
- **결과**: 그림자 맵·광원 수가 그대로라 성능 영향이 거의 없다. 홈 미리보기가 밤에 방문하면 저녁 조명으로 보이는 것은 의도된 동작이다.

## ADR-010 메뉴소개 '읽는 메뉴' 재구성
- **상태**: 확정 (2026-11-16)
- **맥락**: '전체' 필터에서 같은 모양 카드 23장이 이어져, 디자인 규칙(05 §9 '카드 키트 지양')과 어긋나고 카테고리 구분이 약했다.
- **결정**: 카테고리별 섹션 + 대표 메뉴(`lead`) 큰 카드. 대표 카드 모양은 나머지 카드 수로 계산해 3열 격자를 꽉 채운다(`getLeadLayout`, 순수 함수로 단위 테스트). 필터·URL 동기화·`article` 구조는 그대로 둬 기존 E2E를 유지한다.
- **결과**: 메뉴 데이터가 바뀌어도 격자가 자동으로 맞춰진다. 태블릿(2열)에서는 나머지 수가 홀수면 마지막 줄에 카드 한 장이 남을 수 있다(수용).
